# SwiftDL

一个用 Go 从零实现的「多源 · 分块 · 并发」下载器，核心目标是把 HTTP 分块多线程做到极致：把大文件切成大量小块，用多条连接同时拉取，并在中断后精确续传。

界面参考迅雷桌面端的布局（工具条 + 左侧分类 + 列表 + 状态栏），后端是一个纯 Go 标准库实现的本地服务，编译产物是单个可执行文件，无需安装运行时。

> 说明：本项目与迅雷官方无关，未使用其 Logo、图标或商标资源，界面仅作布局参考。

## 特性

### 下载引擎

- **HTTP Range 分块**：`Range: bytes=start-end` 并发拉取，响应必须为 `206 Partial Content`
- **并发分块**：线程数可配置（默认 16，上限 128），每个线程独立连接、独立分块
- **多源下载**：同一文件可填多个镜像地址，分块按 `index % 源数` 轮流分配，源之间限速不同时可叠加带宽
- **断点续传**：每个分块记录 `start / end / done`，暂停、退出、进程重启后从断点继续
- **崩溃恢复**：启动时把 `downloading` 状态回退为 `queued` 并自动续传
- **预分配文件**：启动即按最终大小占位，分块按偏移 `WriteAt` 直接写入，无需最后合并
- **完整性校验**：完成后可做 SHA256 / MD5 校验，不匹配直接标记失败
- **失败重试**：分块级重试，可配置次数与退避间隔
- **限速**：全局 + 单任务，令牌桶实现，运行中修改立即生效

### 任务管理

- 任务队列与并发任务数控制
- 暂停 / 恢复 / 取消 / 删除（可连同本地文件一起删）
- 实时速度、进度、剩余时间、分块状态
- 任务与分块进度持久化到 `data/tasks.json`（临时文件 + rename 原子写入）

### 界面

- 标题栏、工具条、左侧分类（全部 / 正在下载 / 已完成 / 失败）、六列表格、底部状态栏
- 新建任务对话框：支持多行地址批量添加、实时探测大小与是否支持分块、高级设置折叠
- 选中任务后由工具条操作，双击行打开所在目录，`Delete` 键删除
- 无第三方前端框架，单个 HTML + CSS + JS，内嵌进二进制

## 快速开始

### 环境要求

- Go 1.22 及以上（使用了 `net/http` 的方法路由 `GET /api/...`）
- Windows / macOS / Linux

### 运行

```bash
# 方式一：双击 run.bat（Windows，自动编译并启动）
# 方式二：命令行
go build -o bin/swiftdl ./cmd/swiftdl
./bin/swiftdl
```

启动后自动打开浏览器（可加 `--no-browser` 关闭），默认地址：

```
http://127.0.0.1:8765
```

### 命令行参数

| 参数 | 说明 | 默认值 |
|---|---|---|
| `--port` | 监听端口 | `8765` |
| `--data` | 数据目录（配置与任务进度） | `./data` |
| `--no-browser` | 启动后不自动打开浏览器 | `false` |

### 测试

```bash
go vet ./...
go test ./...
```

覆盖：分块切分连续性、Range 下载内容一致、**断点续传后文件哈希一致**、暂停后恢复、哈希不匹配报错、REST 接口全流程。

## 使用说明

1. 点左上角 **新建**，粘贴下载地址（可多行批量），实时提示文件大小与是否支持分块
2. 需要时展开 **高级设置**：镜像地址、线程数、限速、重试次数、校验值
3. 添加后在列表里查看进度；选中任务可用工具条的 开始 / 暂停 / 删除 / 打开目录
4. 设置弹窗里可改默认保存目录、同时下载任务数、全局限速、默认线程数、代理

## 技术实现

### 分块策略

```
块大小 = 文件大小 / (线程数 × 4)          // 让每个线程始终有排队任务
块大小 = clamp(块大小, 1 MiB, 16 MiB)     // 避免请求过碎 / 重试代价过大
块数   = ceil(文件大小 / 块大小)
```

举例：14.6 GiB 文件、16 线程 → 理想块 233.8 MiB → 被压到 16 MiB → **936 个分块**（935 个满块 + 1 个尾块）。

注意：对大文件，块数基本由 16 MiB 上限决定，线程数只影响「同时有多少块在跑」。

### 断点续传

- 每个分块维护 `done`（已写字节），恢复时从 `start + done` 重新发 Range
- 文件预先 `Truncate` 到最终大小，分块用 `WriteAt` 写各自偏移，互不干扰
- `tasks.json` 每 2 秒最多持久化一次，避免高频写盘
- 进程重启后 `downloading` → `queued`，由队列自动续传

### 限速

令牌桶按「已发送字节 / 理论用时」差值阻塞，支持全局与单任务两级，修改配置即时生效，不用重启任务。

### 并发模型

管理器为每个任务创建一代 Runner（带 `gen` 代际号），Runner 内部用 `threads` 个 goroutine 消费分块索引 channel；暂停/恢复通过取消 context 并重建 Runner 实现，代际号用于丢弃旧实例的迟到回调，避免竞态。

## 配置

`data/config.json`：

| 字段 | 说明 | 默认 |
|---|---|---|
| `saveDir` | 默认保存目录 | 用户下载目录 |
| `maxConcurrentTasks` | 同时下载的任务数 | `3` |
| `defaultThreads` | 新建任务默认线程数 | `16` |
| `globalSpeedLimit` | 全局限速（字节/秒，0 不限） | `0` |
| `retries` | 分块重试次数 | `3` |
| `retryDelayMs` | 重试间隔（毫秒） | `1000` |
| `proxy` | 代理地址，如 `http://127.0.0.1:7890` | 空（走环境变量/系统代理） |

## REST API

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/state` | 任务列表 + 全局统计 + 配置 |
| GET | `/api/config` | 读取配置 |
| PUT | `/api/config` | 更新配置 |
| POST | `/api/probe` | 探测 URL（大小、Range 支持、文件名） |
| POST | `/api/tasks` | 新建任务 |
| POST | `/api/tasks/{id}/pause` | 暂停 |
| POST | `/api/tasks/{id}/resume` | 继续 / 重试 |
| POST | `/api/tasks/{id}/cancel` | 取消 |
| POST | `/api/tasks/{id}/reveal` | 打开所在目录 |
| DELETE | `/api/tasks/{id}?deleteFile=1` | 删除任务（可选删文件） |

新建任务请求体示例：

```json
{
  "url": "https://example.com/big.iso",
  "mirrors": ["https://mirror.example.com/big.iso"],
  "dir": "D:\\Downloads",
  "threads": 32,
  "speedLimit": 0,
  "retries": 3,
  "expectedHash": "sha256:..."
}
```

## 常见问题

**速度上不去？**

先看链路：`netsh wlan show interfaces` 或任务管理器里的网卡速率。若 Wi-Fi 协商速率只有 200~300 Mbps，实际 TCP 吞吐上限约 20~25 MB/s，此时加线程没有意义。有线千兆能到 90~110 MB/s。另外代理节点（如 Clash 机场）自身可能限速 10~20 MB/s。

**提示「不支持 Range（单连接）」？**

服务器没返回 `206`，只能顺序下载，无法分块并发。

**需要科学上网的资源怎么办？**

在设置里填 HTTP 代理（如 `http://127.0.0.1:7890`）。想直连镜像时可以把地址换成镜像域名，或把镜像填进「镜像地址」实现多源。

**会不会下载到一半文件就完整大小了？**

会。文件是预分配的，未下载区域是 `0`，下载完成后才是完整内容——这是并行写入的正常现象。

**数据在哪？**

- 配置：`data/config.json`
- 任务与分块进度：`data/tasks.json`
- 文件：你设置的保存目录

## 已知限制

- 未实现 P2P / P2SP（迅雷私有协议依赖庞大用户网络，个人项目不具备条件）
- 未做浏览器下载接管、SOCKS5 专属配置（现支持 HTTP 代理与环境变量代理）
- 不支持 HTTP/3（已使用 HTTP/2 多路复用）
- 续传时只比对大小，未强制校验 `ETag` 判断源文件是否被替换
- 单文件分块元数据随文件大小增长，超大文件（数千块）时 `tasks.json` 会到几百 KB
